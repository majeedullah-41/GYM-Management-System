# Receipts & Printing Module

**Module:** Receipts & Printing  
**Priority:** P0 — Critical  
**Status:** Planned

---

# 1. Purpose

The Receipts module is responsible for generating, previewing, and printing payment receipts.

It does NOT create financial transactions.

The Finances/Payments module creates the payment.
The Receipts module turns that payment into a printable receipt.

Core flow:

Payment
  ↓
Receipt Data
  ↓
Receipt Template
  ↓
Preview
  ↓
Print

---

# 2. Primary Goals

The module should allow staff to:

1. Print a receipt immediately after receiving payment.
2. Reprint an existing receipt.
3. Preview a receipt before printing.
4. Use a consistent professional receipt layout.
5. Support a configurable gym header.
6. Clearly show payment information.
7. Clearly identify voided receipts.
8. Print without modifying the underlying payment.

---

# 3. Important Principle

A receipt is a representation of a payment.

It is NOT the payment itself.

```text
Payment
    ↓
Receipt
```

Never:

```text
Receipt
    ↓
Create Payment
```

The payment record is authoritative.

# 4. Receipt Number

Every payment should have a unique receipt number.

Example:

RCP-000001
RCP-000002
RCP-000003

Receipt numbers are generated by the Finances backend/service.

The Receipts module must never generate a new receipt number when reprinting.

# 5. Reprinting

If:

RCP-000248

was already printed once, printing it again must produce:

RCP-000248

not:

RCP-000249

Reprinting must never create another payment.

# 18. Printing Failure

Printing is an external operation and may fail.

Examples:

Printer unavailable
Printer disconnected
Invalid printer
OS print failure

If printing fails:

Payment:
SUCCESS

Printing:
FAILED

The payment remains valid.

# 19. Printing Failure UI

Show:

Payment recorded successfully.

The receipt could not be printed.

You can try again from the payment record.

[ Try Again ] [ Close ]

Never tell the user:

Payment failed

if the database transaction already succeeded.

# 20. Print Success

After successful printing:

Receipt printed successfully.

The UI should not create another payment.

# 21. Print History

The initial version does not require a complete print-history system.

Optional future fields:

printed_at
print_count
last_printed_at

Only implement these if required.

# 22. Receipt Storage

Do NOT store a complete rendered receipt document for every payment unless necessary.

Prefer:

Payment Data
+
Receipt Template
+
Gym Settings

to generate the receipt.

# 23. Historical Receipt Integrity

There is an important distinction between:

Payment History

and:

Current Gym Settings

If the gym name changes later, decide whether historical receipts should show:

Old gym information

or:

Current gym information

This must be explicitly defined in the data/receipt specification.

Do not let this behavior happen accidentally.

# 24. Recommended Historical Strategy

For financial documents, the safest approach is to preserve the information necessary to reproduce the original receipt.

The exact snapshot fields should be defined in:

DATABASE-SPECIFICATION.md

and:

RECEIPT-TEMPLATE.md

# 29. Phone Number

Member phone number should not be printed by default unless the receipt design explicitly requires it.

The system should support the gym's chosen printer format.

A4

# 31. Thermal Receipt

If a thermal receipt printer is used, the receipt should be optimized for narrow paper.

Example:

```text

Ahmad Khan
```

# 32. A4 Receipt

If the gym uses a normal printer, an A4-compatible receipt can be used.

However, do not design the UI specifically for A4 if the gym intends to use thermal printing.

Printer requirements should be established before implementation.

# 70. Final Principle

The receipt is a printable representation of financial history.

Therefore:

PAYMENT
   │
   ├── Financial Record
   │
   └── RECEIPT
          │
          ├── Preview
          ├── Print
          └── Reprint

Printing is read-only.

A receipt can be printed ten times without creating ten payments.

The financial record remains the single source of truth.
